# Easy Painter 开发测试数据包操作手册

适用：**v0.19.0 / Flyway V9 / macOS**。数据包第 1 版。

本包只包含测试数据、图片文件、导入脚本和手册。**不包含镜像，不下载、构建或启动任何服务。** 同事自行准备项目代码及本地环境；导入后使用真实后端、真实数据库和 RustFS，不使用 API mock。

数据全部为程序生成的开发样例，不来自生产用户。没有生产 `.env`、真实邮箱、密码哈希、上游 Key 或服务器地址。

## 1. 包内文件

```text
easy-painter-dev-data-v0.19.0/
├── README.md             本手册
├── import_data.py        导入工具
├── data.json             业务数据与对象清单
├── MANIFEST.json         文件 SHA-256 清单与版本
├── VALIDATION.md         实际验证结果及覆盖范围
└── objects/
    ├── media/           生成图片、社区副本与 WebP 缩略图
    └── reference/       参考图片与 WebP 缩略图
```

共 3 个测试用户、12 条任务、12 条扣费记录、16 条积分流水、5 张参考图、2 个社区收录副本、4 条投稿状态、4 条收藏引用；共 35 个对象文件。

## 2. 同事自行准备本地环境

1. 在自己的 Git 克隆目录使用 v0.19.0 对应代码。需要提交前端改动时，在自己的开发分支工作。
2. 按仓库 README 自行准备 Python 3.12、uv、Node.js 22+，以及 PostgreSQL 16、Redis、RustFS。服务可以用自己的 Docker 环境运行。
3. 从仓库 `.env.example` 创建自己的 `.env`，设置 **`APP_ENV=development`**，填写本地数据库与 RustFS 凭据、独立的 JWT 密钥及 `ADMIN_SECRET_KEY`。不要使用生产 `.env`。
4. 在**空开发数据库**上完成 Flyway V1–V9 迁移，并准备两个空的私有 bucket，分别对应 `MINIO_BUCKET` 和 `MINIO_REFERENCE_BUCKET`。
5. 导入前只运行基础设施，暂不启动 API、worker、dispatcher。`make deps` 会同时启动后台任务，因此不要直接用它作为导入前的“仅启动依赖”命令。

导入工具不会创建数据库或数据库结构，也不会清空已有数据。迁移生成的默认用户组允许存在；如果已经启动过 API 并生成用户，请另建一个空开发数据库再迁移。

## 3. 校验数据包

解压后，在包目录中执行：

```bash
python3 import_data.py --check
```

此命令仅使用 Python 标准库，不访问数据库或对象存储。也可以在 ZIP 所在目录执行：

```bash
shasum -a 256 -c easy-painter-dev-data-v0.19.0.zip.sha256
```

## 4. 导入测试数据

打开终端，进入**自己项目的 backend 目录**。把下面的包路径替换为实际解压位置；`--repo ..` 指自己的项目根目录。

```bash
cd /path/to/your/easy-painter/backend
uv sync
uv run python /path/to/easy-painter-dev-data-v0.19.0/import_data.py \
  --repo .. \
  --confirm-empty-local
```

脚本读取自己项目根目录的 `.env`，使用其中的数据库名、账号、密码和 bucket 配置。在 macOS 宿主机运行时，**数据库和 S3 连接地址强制使用 `127.0.0.1`**，默认端口为 5432 和 9000。自定义端口时加上：

```bash
uv run python /path/to/easy-painter-dev-data-v0.19.0/import_data.py \
  --repo .. --db-port 15432 --s3-port 19000 --confirm-empty-local
```

导入会检查版本、空库和空 bucket，写入真实图片并逐个回读校验，在一个数据库事务中写入业务记录；不会导入排队任务或后台待投递事件。图片日期、任务时间和保留期限整体平移到当前导入时刻，保留“已过期”“即将过期”和 VIP 等场景的相对关系。

导入成功后，随机生成的测试登录密码保存在**数据包目录的 `.local/ACCOUNTS.txt`**。三个账号使用相同的本次测试密码：

| 账号 | 用途 |
| --- | --- |
| `demo` | 普通组，公开总开关已开启，主要业务样例 |
| `vip` | VIP，默认 30 天保留期 |
| `private` | 普通组，公开总开关关闭，测试投稿前置检查 |

管理后台仍使用**你自己项目 `.env` 中的 `ADMIN_SECRET_KEY`**。数据包不会替换它，也不会导入 JWT、数据库或 RustFS 的服务凭据。

如果选择在已有后端容器中运行工具，可使用 `--container-network`；仅允许 `postgres` 与 `rustfs:9000` / `minio:9000` 服务名，并仍要求 `APP_ENV=development` 和空库、空 bucket。容器内需能读取数据包和项目目录；这不是 macOS 的默认步骤。

## 5. 启动并测试

导入完成后，按仓库 README 启动 API、worker、dispatcher 和前端。本地常规开发流程是分别运行 `make deps`、`make backend`、`make frontend`；已有自己启动方式的同事继续沿用即可。

默认前端 <http://127.0.0.1:5173>、后端文档 <http://127.0.0.1:8000/docs>。前端通过 `/api` 访问真实后端。

建议验收：

- 用三个测试账号登录；在管理后台确认普通组 48 小时、VIP 720 小时策略。
- `demo` 的生图历史包含成功、失败退款、仅自己可见、已过期记录。
- 测试加入/移出画廊、显示/隐藏提示词、收藏/取消收藏与失效收藏。
- 社区有待审核、已驳回及已通过样例；管理员通过审核后，查看独立社区副本。
- 使用 `private` 账号投稿，确认先要求开启个人公开总开关。
- 打开横图、竖图、方图和缩略图，上传参考图，检查普通用户配额提示。
- 原图已过期的已收录作品仍有社区长期副本；普通过期原图不可访问。

积分有完整的初始余额、预扣、结算/退款关系，启动 dispatcher 后不会因只有余额而缺少流水被对账清零。历史图片标有 `DEV FIXTURE`，代表测试样例，不表示曾调用过真实生图上游。

## 6. 真正生成新图片

`gpt-image-2` 模型默认禁用，上游地址为不可用占位值，Key 为 `not-configured`。登录、历史、画廊、收藏、参考图和审核可以先测试。

要生成新图片，请在管理后台“上游管理”填写团队分配的**独立限额测试渠道**地址与 Key，再在“模型管理”核对模型 ID、参考图能力并启用模型。渠道存于数据库，修改 `.env` 不会覆盖已有渠道。

是否可以测试注册/验证码/找回密码，取决于同事自己配置的测试 SMTP。此包不提供 SMTP 凭据；验收没有调用真实上游生图或发送邮件。

## 7. 重复使用和常见问题

- **重新初始化**：停止自己的应用服务，另建空开发数据库和两个空 bucket、完成迁移，再导入同一 ZIP。工具不提供覆盖或清空已有数据的选项。新导入会生成新密码并刷新相对时间。
- **目标非空**：工具会拒绝导入。不要对生产或其他项目执行清库；使用新的本地测试数据库与 bucket。
- **找不到 app / 缺少依赖**：在项目 `backend` 下用 `uv run python` 执行，并确认 `--repo` 指项目根目录。
- **连接失败**：核对本地服务、端口映射、`.env` 中数据库名/账号和 S3 凭据。脚本不会访问 `.env` 中的远程主机。
- **schema/version 不匹配**：本包对应 v0.19.0 / Flyway V9，先准备对应版本的空库；不要硬改生产 migration history。
- **两天后图片过期**：符合普通组策略。需要新一轮完整样例时重新导入空环境，或用 VIP 样例调试。
- **图片上传中断**：本次数据库事务会回滚，工具尝试清理本次写入的对象；如果清理失败，请检查自己的测试 bucket 后再导入。

给下一位同事直接转发**原始 ZIP 和 `.sha256` 文件**。不要把导入后的 `.local` 密码文件、自己配置的上游 Key 或生产冷备一起打包。这份包用于重建本地开发数据，不是生产灾难恢复备份。
