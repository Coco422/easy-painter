# v0.19.0 升级说明与验收

本版本重整作品管理，涉及 Flyway V9 和媒体留存规则。发布需要同时升级 API、worker、dispatcher 与前端。正式发布和生产部署仍须单独获得本版本授权，并使用新的 `v0.19.0` tag。

## 用户操作

| 入口 | 内容与操作 |
| --- | --- |
| 生图历史 `/history` | 所有生成任务，包括排队、生成、成功、失败和图片过期；搜索、日期筛选、查看扣费状态、再次创作、删除 |
| 画廊 `/gallery` | 自己主动加入的作品；分享地址仍是 `/gallery/:username`。总开关关闭时可以整理，仅本人可见 |
| 收藏 `/favorites` | 收藏自己、其他公开画廊和社区作品；只保存引用，不增加权限、不延长期限。失效收藏保留占位，可筛选和清理 |
| 社区灵感 `/` | 管理员导入或审核通过的独立长期内容；画廊公开不会自动成为社区内容 |

作品详情中的“加入画廊”控制个人作品集，允许选择是否公开提示词。“投稿社区”必须先在个人中心开启公开总开关，再确认公开图片和提示词并交由管理员审核。待审不延长图片期限；关闭总开关撤回待审稿件。拒绝时必须填写原因，作者可以重新投稿。

审核通过后生成独立社区副本。个人画廊与收藏优先引用这份长期副本；原始生成文件仍按原期限清理。移出个人画廊、关闭总开关或删除生成记录不会撤下已收录社区内容；社区下架由管理员操作。收藏原作和收录版会合并为同一条引用。

## 数据迁移

- 新增 `favorites` 与 `community_submissions`。旧 `is_favorite` 记录迁入收藏；已有公开标志保留为画廊成员关系，不推断为投稿同意。只有已有社区收录项回填为 `approved`。
- 非 VIP 用户组默认生成图与参考图保留时间改为 48 小时。新成图从完成时起算，参考图从上传时起算。
- V9 执行时，仍有效的非 VIP 存量成图和参考图统一设置为 **迁移事务时间 + 48 小时**。已过期、删除中、已删除对象不复活；仍排队/生成的非 VIP 任务保留期快照改为 48 小时。当前用户归属 VIP 时保留原配置和期限，不重写历史价格或流水。
- 三类资产增加缩略图键、摘要、大小和重试信息。SQL 不读取对象存储；缩略图由后台逐步补齐。
- 迁移仅向前。V9 会实际改写有效期，回滚旧应用不能还原这些时间；需恢复升级前数据库和对象快照，或编写经过审查的补偿迁移。升级后的新收藏/审核记录也不能直接交给旧应用维护。

## 媒体与缓存

列表只读取最长边 640px、质量 75 的 WebP 缩略图；详情和下载按需读取原图。未生成缩略图时显示准备中占位，避免列表回退加载大图。

生成 worker 在原图交付并结算后尝试生成预览，预览失败不会退款或改写成功状态。Dispatcher 每分钟最多调度一次补齐，默认每类最多 2 张；失败按分钟退避，最多 5 次，已过期或正在删除的源文件跳过。需要加速预热时，在后端工作目录使用以下有界命令，可分批执行：

```bash
uv run python -m scripts.backfill_thumbnails --limit 20
```

容器部署可在迁移完成、存储初始化成功后执行：

```bash
docker compose -f compose.yml run --rm --no-deps api python -m scripts.backfill_thumbnails --limit 20
```

普通作品及参考图预览使用稳定地址与 `ETag`，返回 `private, no-cache, must-revalidate`，每次请求（包括 HEAD/304）先校验权限和截止时间。普通媒体禁止进入共享 CDN 缓存；现有独立社区原图接口保留公开缓存。已下载到用户设备的副本无法撤回。

前端共享秒级时钟，已知失效后取消请求、释放 Blob、禁用下载，不刷新全列表、不循环重试。仅网络故障、408、429、5xx 自动重试一次；401/403/404/410 不重试。外部图片链接不附带本站登录凭证。缩略图和原图共用权限与删除队列，源文件删除后缩略图也会清理。

## 接口与兼容

新接口均位于 `/api/v1`：

- `GET /history`，`GET /portfolios/{username}`：分页历史与个人作品集。
- `PUT/DELETE /jobs/{id}/gallery`：明确加入/移出，重复请求幂等。
- `GET /favorites`，`PUT/DELETE /favorites/{job|inspiration}/{id}`，`DELETE /favorites/unavailable`：引用收藏与清理。
- `POST/DELETE /jobs/{id}/community-submission`：提交（必须 `consent_public_prompt: true`）与撤回。
- `GET /admin/community-submissions`，`PUT /admin/community-submissions/{id}`：管理员筛选和审核，决定为 `approve` 或 `reject`。
- `GET /artworks/{job|inspiration}/{id}`，`GET/HEAD /artworks/{job|inspiration}/{id}/file?variant=thumbnail|original`：作品元数据和鉴权媒体。
- `GET/HEAD /reference-images/{id}/preview`：私有参考图缩略图。

旧 `/gallery*`、`/jobs/{id}/public`、`/jobs/{id}/favorite` 继续兼容；旧收藏操作使用新收藏表，旧画廊也可返回社区永久副本。旧直接收录入口只能处理用户已提交的待审作品，不能绕过投稿同意。前端不再使用旧画廊页面组件。

## 发布门禁与操作顺序

1. 完成后端全套测试、前端构建、版本校验。记录迁移演练与浏览器验收结果。
2. 发布获得授权后，停写并等待在途任务完成，按 [备份指南](backup-and-disaster-recovery.md) 获取并校验数据库与 RustFS 一致备份。提前告知非 VIP 用户此次存量期限变为升级后 48 小时。
3. 固定新版本镜像，先执行 V9 迁移与存储初始化，再同时启动新 API、worker、dispatcher 和前端。避免新旧实例混跑，旧 worker 的 24 小时快照不可继续处理新任务。
4. 分批预热缩略图，检查缩略图失败记录与删除队列。校验 readiness 的数据库版本为 9。
5. 使用普通/VIP 测试账号核对到期时间、投稿前置开关、待审/拒绝/通过、游客画廊、失效收藏和下载。对原始图片清理与社区副本独立保留做抽样确认。

## 本地验证记录

2026-09-18：使用独立临时 PostgreSQL 16.15 与仓库 Flyway 11.10.5 镜像，由空库迁移到 V8、插入非 VIP/VIP/过期/删除中/已删除/排队等样本，再迁移到 V9。有效期、8 条收藏、已收录回填、排队快照和价格保留断言通过。真实 PostgreSQL 并发断言通过：旧会话状态不能绕过公开总开关；同时批准同一投稿只创建一份社区资产。

后端、前端及浏览器最终结果在本次实现清单中记录：[v0.19.0 实现清单](v0.19.0-implementation.md)。本地验证使用模拟图片与隔离数据，不产生上游生图费用，不访问生产数据库。
