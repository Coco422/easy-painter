# 创作工作台重设计 · 草案

> 状态：设计稿，未改动任何应用代码。配套可交互稿见 [workspace-redesign-draft.html](./workspace-redesign-draft.html)（本地起个静态服务打开，右下角可切换「空闲 / 生成中 / 完成 / 尺寸弹层」和深浅色）。
> 对照环境：`main` @ `d8c5cb9`，线上 https://tutu.88888888.dog/create（1440×900 截图见 `shots/create-1440.png`）。

## 1. 为什么现在"繁杂"

不是配色或字体的错。`style.css` 的暖金 / 米白 token 是自洽的，问题在**信息架构**：工作台把「我要画什么」和「系统在做什么、花了多少、还能怎么调」平铺成了同一个视觉层级，于是眼睛没有落点。

具体可量化的几条：

1. **输入面板有 13 个纵向块**（`GeneratePanel.vue`）。模式三选 → 提示 → 创作用途 → 描述 → 工具栏 → 示例 → 视觉风格 → 图中文字 → 尺寸 → 数量 → 高级折叠 → 主按钮 → 计费。1440×900 下，尺寸和数量已经掉到首屏之外。
2. **同一个概念出现三次**。「创作用途」下拉（左栏）、右侧四张模板卡、再加上「填入示例描述」按钮，都在做同一件事：给用户一个起点。用户不知道点哪个才是"正确入口"。
3. **计费信息散落在 5 处以上**：`billing-estimate` 两块（预计消耗 / 当前余额 + 两行解释）、模型下拉里的单价、提交后的 `已提交 N 个任务，实际预扣 X 丝`、`batch-overview` 的已预扣 / 已结算 / 已退回、候选卡上的 `billingLabel`、`version-meta`。生成中同一笔钱被报了三次。
4. **进度是假的**。`CurrentJobCard.vue:103` `loadingProgress = 8 + 状态加成 + elapsed/2500` 封顶 96%，配合 `ritual-log-list` 里轮换的伪日志行。用户真的会盯着 96% 看十分钟，然后觉得"卡住了"。
5. **左栏太窄、右栏太空**。340px 里塞 13 个块；右栏 `min-height: 650px`，空闲态下面有近 170px 空白。对一张"正在画的画"来说，画布应该是主角，现在它和表单平权。
6. **字号几乎全是 11–13px**。`workspace-empty-note`、`creation-mode-hint`、`creation-notice`、`batch-parameters` 全在同一档，注释和正文分不开。`CreatePage.vue:555` 还硬编码了 `'PingFang SC'`，把全站 `LXGW WenKai` 的显示字体断在了工作台里。
7. **三个模式过度显性**。粘贴或拖入图片时 `CreatePage.vue:474` 已经自动切到参考生图了——模式其实是**推导**出来的，却占了第一行最贵的位置。

一句话：现在是"把所有能力都摆出来"，需要改成"默认只摆一件事，其余按需展开"。

## 2. 设计原则

- **一句话输入是唯一主角**。打开页面，视线第一落点是描述框，不是模式、不是用途、不是模板。
- **参数收敛成一行胶囊**。用途 / 风格 / 尺寸 / 数量 / 模型都是低频、有默认值的决定，默认折叠成一行可点的 chip，值和当前状态一眼可见，修改时才展开。
- **计费只说一次，且说在图旁边**。主按钮旁一个数字（`5 丝`），生成中在画布下方一行参数里带上模型和尺寸；其余重复解释全部删掉。
- **画布即舞台**。右栏宽度、高度都给图；空闲态只留一句引导，不再用四张卡替代"开始"。
- **进度只讲真话**。不确定就说不确定（"生成中 · 1 / 2 张已完成"+"已用时 00:14"），不模拟百分比。
- **一屏之内能完成一次提交**。1440×900 不需要滚动就能看到输入、参数、按钮、花费。

- 外壳：`max-width: 1240px`，`grid-template-columns: 396px minmax(0,1fr)`，`gap: 22px`。比现在（1200 / 340 / 24）略宽，让画布拿到更多像素。
- 断点：`≤1080px` 左栏 340；`≤880px` 单列，输入在前、结果在后（和现在的滚动顺序一致，不改交互）；`≤560px` 预计消耗收起，候选栏 62px。
- 右栏 `min-height: 590px` 而不是 650，空闲态内容改为垂直居中，去掉底部空白。

## 4. 生成中状态的详细设计（重点）

现在生成中有三套并行表现：`GenerationWaiting`（quip 打字机）、`CurrentJobCard` 里的 `loading-ritual-panel`（伪进度 + 伪日志）、`batch-overview`（进度条 + 计费）。它们互相不知道对方存在。新稿只保留**一套**：

**画布框内**

- 左上：状态胶囊 `● 生成中 · 1 / 2 张已完成`。整批结束换成 `✓ 已完成`（绿色）。
- 右上：`00:14` 已用时，等宽字体。真实数据（`created_at` 到当前），不造假。
- 中间：呼吸光斑（96px 径向渐变，4.2s）+ 一句 quip（`useGenerationQuips` 现成能力，保留）+ 一句固定说明「结果会自动出现在这里，无需重复提交」。quip 打字机光标保留，但只有一条主句，不再有伪日志区。
- 底部：2px 高的 indeterminate 扫光条。**删掉百分比和阶段文案**（`播种轮廓 / 驯服光线 / 烘焙细节`）。当后端没有真实进度时，indeterminate 比假进度诚实，也更不容易被盯着骂。
- 如果 `status === 'queued'`，状态胶囊文案换成 `排队中`，扫光条降到 30% 透明度——让"排队"和"正在画"在视觉上可区分，这是现在 `GenerationWaiting` 唯一的正确直觉。

**框外**

- 右侧候选栏：84px 竖排。已完成显示缩略图 + `图 1 ✓`，进行中显示转圈 + `图 2`。多张候选同时跑时，用户一眼看到"哪些好了"。现在 `candidate-grid` 是 2 列大卡，占掉半个画布，进行中的卡又是纯占位。
- 下方一行 meta：`提示词摘要 · GPT-Image-2 · 1280 × 720 · 5 丝 × 2 张`。计费只在这里出现一次。
- 操作行：左侧「取消本批剩余」（对应现在的 `stopBatchRequested`），右侧「查看图 1」。不再有第二个"停止"入口。

**完成态**

- 画布直接换成结果图，右下角水印行显示 `1280 × 720 · 48 小时后过期`（`MediaExpiry` 的能力合并成一行）。
- 主操作 `继续修改`（主色），次操作 `下载 / 加入画廊`，右对齐 `加入画布`。版本分支只在存在 V2+ 时才在候选栏下方长出 V1/V2 缩略条——现在 `version-history` 无条件占一行，单张图也显示"修改记录 1"。
- 批量多张时，`继续修改` 作用于当前选中的候选，候选栏的选中态就是"继续修改的对象"。现在 `version-title` + `candidate-caption` + `source-label` 三层标签在描述同一件事。

## 6. 文案取舍

**删除**（当前实际存在的）：

- 「创作工作台 / 从一个想法、一张参考图开始。」——页面标题，重复。
- 「模板帮助组织描述。模型与费用可以在左侧查看，科研内容请核对细节。」——一句话里三个意思。
- 「批量任务按张独立提交，允许部分成功。」「提交后预计剩余 X 丝；批量任务按张独立扣费与退款。」——按钮下方两行小字，全是括号补充说明。
- 「预设会补充到描述之后，实际效果取决于所选模型。」——高级区提示，改成 pill 的 tooltip。
- 「结果会自动显示在这里，无需重复提交。」→ 保留在**生成中**的 fix hint 位置，别的地方删。
- `播种轮廓 / 驯服光线 / 烘焙细节 / 封装成图`、`世界调试台`、16 行伪日志。

**保留并强化**：

- quip「给云层办理临时身份证」这类——这是全站最有性格的资产，让它成为生成中画面的唯一主角（现在被日志行稀释了）。
- 「正在给远处的山重新摆正」式的短句，21px display 字体，一行。
- 尺寸弹层那句「低成本渠道对尺寸的执行并不严格，成图以实际比例为准」——诚实且必要，保留，但放在弹层内而不是入口处。

## 7. 落地顺序（建议分三步，每步都能单独上线）

1. **纯样式重排**（不改任何逻辑）：`CreatePage` 删标题块、`GeneratePanel` 拆 pill 行、删计费重复、修 `PingFang` 硬编码。风险最低，能立刻检验"注意力是否收回来了"。
2. **结果区重写**：`CreationVersions` 换成 rail + stage + meta + actions。需要保留全部语义（aria、focus、版本分支、画布目标选择），逐条对照现有测试 `frontend/tests/*.test.mjs`。
3. **清理旧等待态**：`CurrentJobCard` / `CurrentJobBatch` / ritual CSS 下线。这一步可以等 2 上线观察一段时间再做。

后端零改动：所有字段（`billing_status`、`media_state`、`created_at`、`credit_cost`、候选 membership）在现有 `JobDetailResponse` 里都有。

## 8. 风险与待确认

- **候选栏 84px 是否需要水平滚动**：一次 4 张时竖排 84×4 + 间距 ≈ 372px，1440 宽下可以；≤880 单列时改为横排。
- **删除"创作用途"下拉后，`creationTemplates` 的示例填充能力**需要迁进 pill 弹层，注意已输入文案时不能覆盖（`applyTemplate` 现在的"保留用户描述"逻辑要保留）。
- **AI 生图结果画布高度**：稿里用 `flex:1` 撑满结果区，但纵横比不同的图（16:9 vs 9:16）会导致每次生成后页面高度跳动。需要在 `frame` 上用 `aspect-ratio` + `max-height` 双约束，`resolveImageLayout` 已有能力。
- **≤900px 的窄屏布局**：输入与结果改为单列，主画布显示在候选栏之前，减少窄视口下候选区对画布的挤压。
- 是否需要保留"查看历史 / 全部历史"顶部入口——稿里放进了 rail 右侧，语义和现在 `workspace-results-heading` 的 `查看历史` 一致。
