# 独立运营站点

共同功能以 `main` 为维护源，代理站使用 `ray/agent-site`。修复和功能先进入公共分支，再合入代理分支；不要在两个分支分别实现同一修复。站点差异通过环境配置维护，禁止提交真实域名、服务器地址、密钥或用户数据。

## 站点配置

- `SITE_NAME`：站点名称。
- `RELATED_SITES_ENABLED=false`：隐藏菜单、页脚中的主站、文档、代充跳转和仓库版本入口。默认 `true` 保持公共站行为，元数据未加载时暂不展示外链。画布开源署名继续保留。
- `ZPAY_ENABLED=false`，不配置支付商户：关闭在线支付，个人中心隐藏充值入口；兑换码与管理员调额继续可用。充值目录读取失败时也不显示入口。
- `REGISTRATION_ENABLED=false`：未配置邮件时关闭公开注册，先由管理员创建测试用户；配置专属邮件服务后再开放。
- 两个站点使用各自的 Compose 项目、数据库、Redis、RustFS、JWT、管理员凭据与上游 key。不要复制主站数据库或使用主站 key。

## 发布与同步

正式版本仍使用全仓库唯一的 `vX.Y.Z` tag，不支持预发布后缀。tag 工作流构建三种镜像；只有提交已属于 `origin/main` 的版本才自动部署主站。独立分支的 tag 跳过该部署，需明确指定独立站目录安装。不要为了触发构建将代理发布提交合到主站。

首次安装在全新目录放置 `compose.yml` 和权限为 600 的 `.env`，固定 `IMAGE_TAG` 为已构建的正式版本，并通过 `COMPOSE_PROJECT_NAME` 区分实例。先启动基础设施并执行迁移，再启动应用；确认 readiness、支付关闭、外链隐藏、两个独立 key 和真实生图交付后才对外开放。

后续更新使用 `scripts/deploy-production.sh`，传入目标版本与该站专属部署目录。每站独立备份、验收、回退，遵守 `docs/backup-and-disaster-recovery.md`，禁止混用数据目录。回退仅使用该站已验证的旧正式 tag，数据库迁移不自动逆向回退。
